# 체크포인트 답변

## 1. 모델 배포의 필요성

### 문제 1. `.pth` 파일만 전달했을 때, 상대방이 모델을 바로 사용할 수 없는 이유는 무엇입니까?

**답변:** `.pth` 파일에는 보통 가중치만 저장된다. 따라서 파일을 받은 사람은 같은 모델 클래스 정의, 전처리 방식, PyTorch 및 관련 라이브러리 버전까지 갖추어야 모델을 복원하고 사용할 수 있다.

### 문제 2. 모델 학습(Training)과 모델 배포(Serving)의 핵심 차이를 한 문장으로 설명할 수 있습니까?

**답변:** 학습은 데이터로부터 모델 파라미터를 최적화하는 과정이고, 배포는 학습된 모델을 사용자가 안정적으로 요청하고 결과를 받을 수 있게 제공하는 과정이다.

### 문제 3. 모델 배포에서 사용자와 서버가 소통하는 방식은 무엇입니까?

**답변:** 사용자는 정해진 API 규약에 맞춘 HTTP 요청과 JSON 데이터를 서버로 보내고, 서버는 전처리·추론·후처리 결과를 JSON 응답으로 반환한다.

## 2. 가상환경과 requirements.txt

### 문제 1. 가상환경 없이 `pip install`을 하면 패키지가 어디에 설치됩니까? 그것이 왜 문제가 될 수 있습니까?

**답변:** 현재 시스템 Python의 전역 패키지 영역 또는 사용자 패키지 영역에 설치된다. 프로젝트마다 필요한 버전이 다르면 서로 충돌하고, 다른 사람이 같은 실행 환경을 재현하기 어렵다.

### 문제 2. `pip freeze`로 생성한 파일과 직접 작성한 `requirements.txt`의 차이는 무엇입니까?

**답변:** 직접 작성한 `requirements.txt`는 프로젝트가 직접 사용하는 핵심 의존성과 허용 버전 범위를 의도적으로 기록한다. `pip freeze` 또는 `uv pip freeze` 결과는 설치된 모든 직접·간접 의존성을 정확한 버전으로 기록하므로, 현재 환경을 더 엄밀하게 재현하는 데 적합하다.

### 문제 3. 동료에게 프로젝트를 전달할 때, `.venv` 폴더 대신 무엇을 공유해야 합니까?

**답변:** `.venv` 폴더 자체 대신 `requirements.txt`, 필요하면 `requirements_freeze.txt`, 프로젝트 소스 코드 및 실행 방법을 공유해야 한다. 받은 사람은 자신의 운영체제에서 새 가상환경을 만들고 의존성을 설치한다.

## 3. RESTful API와 JSON

### 문제 1. 모델 추론 요청에 GET이 아닌 POST를 사용하는 이유는 무엇입니까?

**답변:** 모델 추론은 텍스트나 이미지처럼 길고 복잡한 입력을 요청 본문에 담아 처리하므로 일반적으로 POST를 사용한다. GET은 조회 목적이며 본문 사용이 표준적이지 않고 URL 길이 제약도 있다.

### 문제 2. 상태 코드 `422`는 어떤 상황에서 발생합니까?

**답변:** `422 Unprocessable Entity`는 요청 자체는 도착했지만 입력 데이터의 타입, 필수 필드, 형식 또는 값이 API의 검증 규칙에 맞지 않을 때 발생한다.

### 문제 3. `requests.post(url, json=data)`에서 `json=` 파라미터는 내부적으로 어떤 일을 합니까?

**답변:** Python 객체를 JSON 문자열로 직렬화하고, 요청 본문에 넣으며 `Content-Type: application/json` 헤더를 설정한다.

### 문제 4. Python의 `True`는 JSON에서 어떻게 표현됩니까?

**답변:** 소문자 `true`로 표현된다. 마찬가지로 `False`는 `false`, `None`은 `null`이다.

## 4. 모델 직렬화

### 문제 1. `state_dict`로 저장한 `.pth` 파일을 불러올 때, 모델 클래스 정의가 필요한 이유는 무엇입니까?

**답변:** `state_dict` 파일에는 파라미터 텐서만 들어 있고 모델 계층 구조와 `forward()` 구현은 들어 있지 않다. 따라서 같은 구조의 모델 클래스를 먼저 선언한 후 가중치를 연결해야 한다.

### 문제 2. `torch.jit.trace`와 `torch.jit.script`는 각각 어떤 상황에서 사용합니까?

**답변:** `torch.jit.trace`는 더미 입력이 실제로 지나간 연산 경로를 기록하므로 입력에 따른 분기가 없는 모델에 적합하다. `torch.jit.script`는 Python 코드를 분석하므로 `if/else`, 반복문처럼 입력에 따라 달라지는 제어 흐름이 있는 모델에 사용한다.

### 문제 3. ONNX의 가장 큰 장점은 무엇이며, 어떤 상황에서 선택해야 합니까?

**답변:** ONNX의 가장 큰 장점은 프레임워크와 언어에 덜 종속적인 공용 모델 포맷이라는 점이다. PyTorch 없이 ONNX Runtime으로 실행하거나 TensorRT·OpenVINO 같은 추론 엔진으로 최적화해야 할 때 선택한다.

### 문제 4. `torch.onnx.export()`에서 `dynamic_axes`를 지정하지 않으면 어떤 문제가 생길 수 있습니까?

**답변:** 내보낼 때 사용한 더미 입력의 배치 크기(보통 1)가 고정될 수 있다. 그러면 실제 서비스에서 여러 입력을 한 번에 처리하는 배치 추론이 실패하거나 제한된다.
